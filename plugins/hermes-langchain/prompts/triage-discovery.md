Triage 단계: discovery

검증된 intake의 investigation target만 기준으로 Codebase Memory와 Semble을 사용해 production symbol, caller/consumer, nearest test 후보를 찾는다. 이 단계는 후보 locator를 정하는 bounded discovery이며 구현을 판정하는 단계가 아니다.

Codebase Memory project 이름을 하드코딩하지 않는다. 먼저 `list_projects`를 `has_more=false`까지 순회한다. assignment `workspace_path`와 `root_path`가 일치하는 후보에만 `index_status(verbose=true)`를 한 번 호출하고, 각 결과를 `project`, `root_path`, `root_exists=git.root_exists`, `git_head=git.head_sha`로 정규화한다. KWC assignment의 `workspace_path`, 실제 root, 실제 Git HEAD가 모두 일치하는 project가 정확히 하나일 때만 그 이름으로 검색한다. 삭제된 root, 다른 workspace, stale HEAD와 중복 match는 신뢰하지 않는다. 일치 project가 없거나 여러 개면 Codebase Memory를 typed unavailable로 기록하고 Semble·local source 탐색으로 전환한다.

각 target의 intake `locator`는 이미 검증된 첫 production candidate이므로 그 locator 자체를 다시 검색하지 않고 그대로 보존한다. Candidate 확장은 target마다 Codebase Memory `search_code|search_graph|trace_path` 중 가장 적합한 호출 **하나만** 사용하고, `search_graph`를 선택하면 `include_connected=true`, `limit=10`, 첫 page만 사용해 caller/dependency 후보를 함께 받는다. Candidate가 최대 5개이므로 `has_more=true`여도 offset을 증가시키거나 limit을 키워 pagination하지 않는다. 첫 순회 뒤 cross-module producer public source가 없는 경우에만 모든 target을 합쳐 Codebase Memory 보완 호출을 최대 한 번 사용한다. Question이 producer, cross-module 또는 상대 module 공개 API/error seam을 요구하면 같은 consumer module의 port·adapter만으로 완료하지 않는다. Exact producer-owned public production source를 candidate에 반드시 포함하고, 아직 없으면 두 번째 same-path symbol이나 두 번째 test보다 먼저 확보한다. 모든 target 작성 뒤 이 조건을 다시 확인하고 누락 시 global completion query를 한 번 사용한다. Nearest test가 없는 target은 target type 이름들을 하나의 regex로 묶어 `src/test` 아래를 찾는 local `search_files` 호출을 최대 한 번 사용한다. Semble fallback은 그 뒤에도 caller/consumer 또는 cross-module producer가 없는 target을 묶어 최대 한 번 사용한다. Target 질문이 layer, package, contract ownership 또는 convention 적합성을 묻는다면 loaded project context가 지정한 governing repository guide를 `document` candidate로 포함한다. Project context가 해당 경로를 기준 문서로 지정하고 실제 파일이 존재할 때, layer/package/public contract 변경에는 `docs/architecture.md`, domain 용어·error ownership 변경에는 `docs/domain-glossary.md`를 각각 관련 candidate로 포함한다. Error ownership, error contract 또는 code/message 복제를 묻는 target에는 `docs/domain-glossary.md`가 mandatory이며 exact producer error symbol을 확보한 뒤 두 번째 producer symbol이나 두 번째 test보다 우선한다. Shared document candidate는 document/current-state impact target 하나에만 붙이고 artifact 전체에서 재사용하며, target별 5개 제한을 넘기면 반복 production method보다 이 governing document를 우선한다. 같은 target에 검색과 trace를 연속 실행하거나 Codebase Memory·Semble·local search를 모두 반복하지 않는다. 여러 target이 같은 seam이나 test를 공유하면 기존 결과를 재사용한다. 같은 path의 class/method candidate는 exact target을 포함해 최대 2개만 유지하고, 나머지 자리는 반복적인 same-file method보다 caller/consumer, nearest test, cross-module producer public source를 우선한다. target별 candidate는 이들을 합쳐 최대 5개로 제한한다. 이후 gap evidence, verification evidence, production seam, contract-change evidence로 사용할 구현 locator는 모두 이 accepted discovery candidate pool에 포함해야 한다. 검색 결과는 locator 후보이며 구현 사실의 증거로 확정하지 않는다.

`kwc-triage-discovery-v2` JSON을 작성한다. top-level은 `schema`, `targets`, `tool_usage`, `fallbacks`, `codebase_memory`다. `fallbacks`는 실제 사용한 fallback마다 정확히 `kind`, `reason`, `target_ids`를 가진 object의 배열이며 사용하지 않았으면 빈 배열이다. `codebase_memory.projects[]`는 raw tool 응답을 복사하지 않고 정확히 `project`, `root_path`, `root_exists`, `git_head`만 가진다. `project`에는 tool의 project name을 쓰며 `name`, `branch`, `nodes`, `edges`, `size_bytes`를 넣지 않는다. `resolution`에는 KWC가 재계산할 typed result를 기록한다. available `resolution`은 정확히 `status`, `project`, `reason`, `git_head`만 가지며 `status=available`, exact `project`, `reason=workspace-and-head-match`, 현재 `git_head`를 사용한다. unavailable `resolution`도 정확히 같은 네 필드만 가지며 `status=unavailable`, `project=null`, KWC reason code와 현재 `git_head`를 사용한다. `resolution`에 `root_path`, `root_exists`를 복사하지 않는다. 각 target에는 `target_id`와 하나 이상의 `candidates`를 기록하고, 각 candidate에는 repo-relative `path`, `symbol`(없으면 `null`), `kind`(`production|test|document`), `reason`을 둔다.

`tool_usage`는 nested breakdown이 아니라 정확히 두 개의 non-negative integer만 가진다. `codebase_memory`는 `list_projects`, `index_status`, `search_code`, `search_graph`, `trace_path` 등 Codebase Memory 계열 호출의 합계이고, `semble`은 `search`, `find_related` 등 Semble 계열 호출의 합계다. 예: `"tool_usage": {"codebase_memory": 11, "semble": 1}`. 호출 종류별 하위 object나 추가 field를 만들지 않는다.

assignment의 repo-relative `artifact_file`에 직접 작성한다. 작성 후 `kwc_advance_triage`에 현재 assignment_id와 그 artifact_file 값을 그대로 제출한다. KWC가 다음 단계를 반환하기 전에는 source를 확정하지 않는다.
